# Docs Site

Load this when editing anything under `docs/`, `zensical.toml`, or a generated reference page. The site is
built by zensical (`just docs-check` = strict build, part of `just check`; `just docs-serve` to browse).

## Page → source of truth

| Page | Source of truth | How it gets there |
|---|---|---|
| `docs/index.md` | hand-written | edit directly |
| `docs/mcp/index.md` | `.agents/knowledge/spec/mcp-overview.md` (section `user`) | snippet include at build time |
| `docs/mcp/tools.md` | the running MCP server (`annotools.mcp.server.mcp`) + `.agents/knowledge/spec/*.md` (sections `user`, `user2`) | **generated** by `scripts/gen_mcp_reference.py`; spec text is inlined by the generator |

`docs/mcp/tools.md` is generated — never hand-edit it. Change the tool's docstring, `Field` description, or
its spec, then run `just docs-gen` and commit the result. `scripts/gen_mcp_reference.py --check` (run by
`just docs-check`, `just check`, the CI `docs` job, and the `gen-mcp-reference-check` pre-commit hook)
fails on drift — schema, description, or spec prose — and prints the diff.

## Generator contract (`scripts/gen_mcp_reference.py`)

- Lists tools with `fastmcp.Client(mcp).list_tools()` — the same schemas an agent sees.
- Fixed tool order and tool → spec-file map in `TOOLS`; a tool missing from the map or from the server
  aborts with `ERROR: tool list drift`. Adding an MCP tool means adding it there (with its spec file) and
  regenerating.
- Per tool: `## <name>`, the tool description, a parameter table (name, type flattened from
  `anyOf`/`enum`/`$ref`/`items`/`prefixItems`, default, required, description) from `inputSchema`, then the
  spec's `user` and `user2` sections inlined with `##` headings demoted to `###`. A spec shared by two
  tools (`preview-video.md`, `coordinates.md`) is inlined once, under the first tool; the second tool gets a
  one-line cross-reference.
- Type cells put each alternative in its own code span joined by `\|` (`` `int` \| `null` ``): GitHub needs
  the escape inside tables and Python-Markdown renders `\|` literally inside a code span. Only the
  description column escapes pipes in prose. A parameter without a description falls back to the first
  line of its `items` or non-null `anyOf` branch description.
- Output is deterministic: header comment `generated by scripts/gen_mcp_reference.py — do not edit`, stable
  ordering, no trailing whitespace, one trailing newline. `--output PATH` redirects (tests use it).
- `scripts/check_readme_sync.py` requires the backticked tool names in both README tool tables to equal the
  `## ` headings of `docs/mcp/tools.md`, so a new tool also needs one README row per language.

## Snippet marker convention

`pymdownx.snippets` is enabled with `base_path = [".", "docs"]` and `check_paths = true`, so include paths
are relative to the repository root (`.agents/knowledge/spec/<file>.md:<section>`) and a missing file or
section fails the build; `docs/mcp/index.md` uses it. The generator reads the same markers itself (a spec
without both sections aborts it). Markers are HTML comments on their own lines:

```markdown
<!-- --8<-- [start:user] -->
## Goal
…
## Behavior
…
<!-- --8<-- [end:user] -->
## Acceptance criteria
…
<!-- --8<-- [start:user2] -->
## Out of scope
…
<!-- --8<-- [end:user2] -->
## References
```

Section names must match `[a-z][-_0-9a-z]*`; a repeated name does not concatenate (the first `end` wins),
hence two sections per tool spec. Full rules: `.agents/knowledge/spec-format.md`.

## Keep in sync

| When this changes | Do |
|---|---|
| A tool's parameters, description, or spec text | `just docs-gen`, commit `docs/mcp/tools.md` |
| A tool is added or renamed | `TOOLS` in the generator, its spec with both sections, README rows (both languages), `just docs-gen` |
| A page is added | `nav` in `zensical.toml`; the table above |
| The marker convention | `spec-format.md`, this file, every spec |
